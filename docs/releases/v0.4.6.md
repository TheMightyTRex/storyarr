# Storyarr v0.4.6

## Changed

- **Storyarr everywhere.** Notifications are titled "Storyarr notification", including the ones you already have. The default database name and user are now `storyarr`, and the Docker and development guides and the sample compose files use Storyarr names throughout.
- **Moving from Dewarr is unchanged.** Compose files that set `DB_NAME` and `DB_USER`, as Dewarr's examples do, keep working. The `X-Dewarr-Proxy-Token` header and the `dewarr-` download folder prefix keep their names, so reverse proxies and downloads already in progress need no changes.

- **Container names.** The sample `compose.yaml` names the containers `storyarr` and `storyarr-postgres`, the same as the `docker run` guide. Existing installs keep their own names.

## Fixed

- The optional `deploy/compose.build.yaml` and `deploy/compose.dev.yaml` overrides now match the `storyarr` service in `compose.yaml`, and build or pull Storyarr instead of Dewarr.

## Database

One migration, `storyarr_0086_notification_title`. To go back to v0.4.5, run `python -m app.downgrade storyarr_0085_user_preferences` in the Storyarr container before switching images.
